# Migration Stage 1 — Preparation

Контрольный документ подготовки проекта Salary Online к переносу приложения и PostgreSQL.

## Что проверять перед переносом

1. Синтаксис приложения:
   `npm run check:syntax`

2. Read-only проверка production PostgreSQL:
   `npm run preflight:migration`

   Проверка не изменяет данные. Она выполняется в транзакции READ ONLY и выводит:
   - наличие критических таблиц и колонок;
   - количество записей по основным таблицам;
   - потерянные ссылки на организации;
   - зарплатные записи без организации;
   - зарплатные записи без совпадающего сотрудника/объекта;
   - связи ответственных пользователей между разными организациями;
   - руководителей проектов без назначенных объектов;
   - дубли нормализованных названий организаций, ИНН и ОГРН.

   Код завершения 0 означает отсутствие блокирующих проблем.
   Код завершения 2 означает, что перед переносом нужно устранить блокеры.

3. Liveness:
   `GET /health` → HTTP 200 и `OK`.

4. Readiness:
   `GET /ready` → HTTP 200 и `{"ok":true}`.

   `/ready` возвращает 503, если PostgreSQL недоступна или схема не прошла инициализацию.

## Переменные окружения

Актуальный перечень находится в `.env.example`.

Обязательные для production:
- `DATABASE_URL`
- `SESSION_SECRET`
- `PORT`
- `EMAIL_VERIFY_ENABLED`

Для внешней PostgreSQL:
- `DB_SSL=true` или `sslmode=require` в `DATABASE_URL`.

`DB_ALLOW_PLAINTEXT=true` допустим только при осознанном использовании доверенной приватной сети.

Для почты:
- `SMTP_HOST`
- `SMTP_PORT`
- `SMTP_SECURE`
- `SMTP_USER`
- `SMTP_PASSWORD`
- `MAIL_FROM`

Для нового домена:
- `PUBLIC_URL`
- `APP_ORIGIN`
- при необходимости `ALLOWED_ORIGINS`.

Реальные пароли, DATABASE_URL, SESSION_SECRET и SMTP_PASSWORD в Git не сохранять.

## Базовая схема

`db.sql` является идемпотентным bootstrap-файлом:
- не удаляет существующие данные;
- содержит текущие основные таблицы и индексы;
- поддерживает ранние версии схемы через ADD COLUMN IF NOT EXISTS;
- не содержит статического пароля ADMIN.

Приложение дополнительно запускает `ensureDatabaseSchema()` при старте.

## Условие перехода к Stage 2

К созданию финального backup переходить только если:

- `npm run check:syntax` завершился успешно;
- `npm run preflight:migration` не показывает BLOCKER;
- production `/health` отвечает 200;
- production `/ready` отвечает 200;
- известны и сохранены отдельно от Git все production-переменные окружения;
- согласовано место хранения минимум двух независимых копий dump.

Следующий этап: полный PostgreSQL dump + тестовое восстановление в отдельную БД.
