## Важное правило для следующих этапов

Криптографические миграции существующих данных НЕ добавлять в `ensureDatabaseSchema()`.

Причина: `ensureDatabaseSchema()` запускается автоматически при старте приложения. Шифрование существующих production-данных должно выполняться только отдельным управляемым migration script после:

1. свежего backup;
2. успешного restore test;
3. проверки конкретной партии записей;
4. возможности остановить процесс без повреждения уже существующих данных.

## Существующие автоматические миграции

Текущий startup-код уже содержит нормализацию старых ссылок организаций через `repairOrganizationReferences()`. Это существующее поведение приложения и на Stage 0 не изменяется.

Во время внедрения шифрования бизнес-логику зарплаты и существующие repair-механизмы не смешивать с криптографической миграцией.

## Production checks

Код содержит:

- `/health` — liveness;
- `/ready` — PostgreSQL + schema readiness.

Внешняя проверка production URL должна быть подтверждена отдельно из среды, имеющей доступ к текущему домену приложения.
